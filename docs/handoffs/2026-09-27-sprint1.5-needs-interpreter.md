# Sprint 1.5 Needs Interpreter 交接（2026-09-27）

## 本轮目标与结论

在 Sprint 2 UI 前完成自然语言需求标准化、短会话合并、缺失/不确定槽位检测、只追问所缺信息，以及紧急程度与医疗急症分流。本轮未进行 React、Cesium、PDF、登录、数据库、新路线算法或航空数据工作。指定 Cases 1–6 已通过，原 Sprint 1 27 项未回归；当前状态以 [PROJECT_STATE.md](../PROJECT_STATE.md) 为准。

## 已完成

- `Needs Interpreter` 将行动能力标准化为 `NORMAL`、`MODERATE`、`LIMITED`、`ASSISTED`、`WHEELCHAIR`、`UNKNOWN`，偏好标准化为 `SAFETY_COMFORT`、`TIME`、`LESS_WALKING`、`FEWER_TRANSFERS`、`LOW_COST`、`BALANCED`，紧急程度区分 `NORMAL`、`TIME_SENSITIVE`、`URGENT_TRAVEL`、`MEDICAL_EMERGENCY`、`UNKNOWN`。旧枚举在 Schema 中暂作输入兼容，新解释结果使用新枚举。
- 解释结果新增 `structured_intent`、`planning_state`、`uncertain_fields`、`follow_up_question`、`planning_allowed` 和 `interpretation_summary`；原有必填字段保留。客户端在下轮回传 `planning_state`，服务端不持久化当前 Session 的个人出行信息。已知年龄、行动能力和偏好不重复询问；未确认的紧急性质跨轮保留。
- 单地点无角色时保留 `location_candidate`，不猜起点或目的地。“明天下午”表达为 12:00–18:00 的有时区 `departure_window`，不制造精确 15:00；`UserRequest` 可用 `departure_time:null + departure_window` 表示该范围。
- 胸痛、呼吸困难等明确当前急症优先提示联系 120/当地急救；解释器不生成普通规划请求，`/plan` 和流水线也拒绝直接提交的 `MEDICAL_EMERGENCY` 请求。赶火车仅为 `TIME_SENSITIVE`，紧急去医院但事件性质未明时请求澄清。否定、假设表达和多轮急症状态有回归覆盖。新增行动能力枚举已接入独立 Safety Reviewer。
- 本地解析增加地点角色、时间范围、否定/假设、偏好与行动能力组合语法；未能解析的明确行动/偏好表达会标不确定并请求澄清。产品负责人选择本轮保持本地解析；LLM 服务及隐私边界记为待决，没有向外部模型发送用户文本。

- 项目文档：`docs/DECISIONS.md`、`docs/ROADMAP.md`、`docs/PROJECT_STATE.md`、`docs/HANDOFF.md` 与本文件。

## 关键决定与依据

- D-007 采用客户端回传的短会话状态和显式时间范围，避免服务端长期记忆及对“明天下午”伪造精确时刻。保留旧请求字段与枚举输入，减少既有消费者迁移成本。
- D-008 将 LLM 接入与个人信息传输边界列为待决。当前本地解析满足指定验收场景，但不保证任意自由表达都能正确抽取；不把规则覆盖等同于开放式 LLM 语义理解。
- 用户地点简称保持原文。Case 6 可形成统一 `UserRequest` 并进入规划接口，但“天津大学”“天津医大总医院”不是当前登记 POI 的精确名称；规划返回零候选和明确警告，不把简称静默映射为入口或驾驶快照。

## 未完成、Blocker 与风险

- 没有 LLM 运行时或供应方决定。即使扩展了本地组合语法，任意口语、方言、错别字和长上下文的泛化仍未验证；LLM 接入前需明确模型、隐私、保留期、失败降级，并保留确定性 Schema/安全门控。
- 无真实精确出入口、无障碍、接驳、实时天气、可用车辆或真实低空运营证据；模拟低空不得表述为真实可乘坐。Case 6 的简称地点无法直接匹配现有登记 POI。
- Sprint 2 UI 尚未启动，日程和负责人待确认。本轮指定场景无阻断；真实推荐的数据缺口仍是项目级限制。

1. 产品负责人审阅本轮指定场景的验收证据；采纳后再另行启动 Sprint 2 UI 工作，不在本轮扩展前端。
