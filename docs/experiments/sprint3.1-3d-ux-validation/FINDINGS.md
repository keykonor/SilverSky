# Sprint 3.1 初步发现与决策边界

## Product UX：PARTIAL

首次输入、已理解内容、补充问题、所选方案、视角与重新规划均有明确文字。合成场景和 Chrome 操作证明流程可执行；没有普通老人或子女首次独立使用观察，不能判定“真正容易使用”。200% 原生缩放可操作，但结果页较长，继续输入位于结果之后；“下一步怎么做”与核验任务仍需用户观察。R2 的时间偏好和 R3 的少步行偏好被解释器识别，却未证明生成了不同排序或实际减少步行。

## Reality Consistency：PARTIAL

只读审查核对了两城登记 POI 名称/城市/坐标，天津和深圳模拟起降点与 OD 同城且没有明显跨城跳跃，路线段有来源标记；界面明确 POI 中心点不是入口、OSRM 是静态驾驶模型、模拟起降点和航线不代表真实运营。天津模拟空中段约 0.485 km、两段接驳约 0.994 km，固定 800 m 椭球视觉高度的爬升在约 97 m 水平范围内完成，作为真实低空旅程的视觉代表性较弱；这不是飞行高度/可飞性主张。模拟起降点的水体/用地合理性、真实地形上的航迹裁切和可建设性均未证实。真实入口、车辆、无障碍、天气和航班信息依然缺失。

## 3D Utility：INCONCLUSIVE

相同 `PlanningResult` 的 2D/3D 对照技术条件已固定，切换不改变 Safety。没有真实参与者的六题、时间、误认、过载或晕动数据，不能声称 3D 帮助理解，也不能声称它增加负担。现阶段保留明确的视图切换；是否默认展示 3D 暂缓裁定。若真实测试显示理解无改善、模拟误认或不适增加，应改为可选的“查看立体旅程”。

## Accessibility：PARTIAL

Chrome 原生四档缩放通过核心流程；200% 的九个关键面板横向裁切、四个关键按钮焦点位置和两块地图浮层重叠又经定点自动检查。地图有文字时间线与安全说明，修复后地图区域同步显示所选方案 Safety。Windows Narrator 七项任务未实际完成，故为 `NOT_VERIFIED`；完整焦点顺序、老年用户阅读和运动舒适度不能从 DOM 或 axe 推断。

## Performance：PARTIAL

4×/6× CPU 下基础规划保持可用；禁用 WebGL 时只显示中文降级文字，且不丢方案。高德与 WebGL 同时失败的组合路径也有准确文案和路线文字。最终 30 分钟、30 轮稳定性测试 0 操作失败、0 页面脚本错误、0 WebGL context loss，Viewer 始终为 1；heap 首尾 82.2→90.4 MB、峰值 122.5 MB，未呈现持续单调增长。**控制台错误计数为 1，但脚本未保存原文，不能判明来源或称全程无错误。**低端实体设备/GPU 未验证，因此 Performance 保持 PARTIAL。

## Safety：PASS（本地技术行为）

轮椅缺无障碍证据时拒绝、赶时间不越过安全审查、急症停止普通规划、模糊地点不推断、无路数据不补造、地图切换后 `REJECT` 保持。此 PASS 不授权现实出行建议；用户是否理解模拟性质仍为 `NOT_VERIFIED`。
