# UX-3D-01 实验方案

## 研究问题与条件

相同旅程和安全文案下，Cesium 立体旅程示意是否比高德真实城市地图的平面投影更能帮助用户理解 Ground → Air → Ground，并且不增加模拟运营误解、阅读负担或运动不适？A 为真实城市地图的平面路线视图；B 为 Cesium 立体视图。A/B 读取**同一个** `PlanningResult` 和同一个 `GROUND_AIR_GROUND` `RouteOption`，只切换 V-002 地图视角；禁止重新规划、更换地点、改写 Safety 或隐藏来源提示。

## 参与者与顺序

Phase A：Product Reviewer 与非开发人员可进行任务观察；独立 Agent/WorkBuddy 只能给 `REVIEWER_EVIDENCE`，不得填为参与者。Phase B：优先招募 60 岁以上用户及有帮助父母出行经历的子女。招募、同意与样本数未完成时为 `USER_STUDY_PENDING`。只记录完成任务必需的匿名年龄段、设备经验和使用情况，不保存真实出行地址或个人身份。

参与者随机分为 AB 与 BA 两种顺序，分别看天津或深圳已固定的同一规划结果；两条件的路线卡、安全文字、浏览器、视口、亮度和任务保持一致。两视图之间重置镜头和当前路线位置，记录先看视图的学习效应。若某条件地图加载失败，记录失败及降级，不能把它当作对照完成。

## 无提示任务

打开相应视图后，请参与者独立回答：①旅程从哪里开始；②在哪里从地面转为空中；③空中在哪里结束；④最后如何到达目的地；⑤它是真实运营航线还是模拟未来场景；⑥哪个阶段最缺现实证据。结束后让参与者执行“切换方案”“返回城市地图”“重新规划”，并询问所见方案是否可实际采用。观察员不得在计时期间讲解正确答案；可以记录求助次数。

## 计时与记录

计时从视图稳定显示且参与者开始阅读时开始，到六题全部回答结束；加载等待另记。记录六题原话、正确数、换乘理解、模拟误认、完成时间、求助、操作错误，以及四个 1–5 主观量表和 3D 价值/晕动量表。每次只用匿名编号，使用 [结果模板](RESULT_TEMPLATE.md)。评分和分母见 [METRICS.md](METRICS.md)。任何真实用户证据须写日期、设备、浏览器版本、缩放和参与者类型。

## 预设判断

只有真实参与者的配对结果显示六题正确数和 Ground–Air 转换理解有一致改善，且模拟误认、完成时间、视觉负担和晕动不恶化，才考虑 `SUPPORTED` 和 3D 继续作为模拟方案默认辅助视图。无真实参与者或数据不足为 `INCONCLUSIVE`；若理解无改善或安全误解、明显负担增加，为 `NOT_SUPPORTED`，提出改为可选“查看立体旅程”。小样本仅支持探索性判断，不用显著性术语伪装统计结论。开发者截图、测试脚本和 Agent 评审不能替代这项判定。

## 固定边界

POI 仅为公开对象中心点；OSRM 为静态驾驶模型；模拟起降点与视觉高度没有真实设施或运营含义；地面 `DOWNGRADE`、模拟空中 `REJECT` 不因视图切换改变。若有人把模拟路线当成可运营或把 `REJECT` 当推荐，至少记录 P1，并停止扩大使用承诺。
