# MVP 范围与验收草案

状态：产品目标与边界已确认；Sprint 1、1.5、2 及 Sprint 3 本地 Demo 的实际完成状态见 [PROJECT_STATE.md](PROJECT_STATE.md)。下列能力同时包含原始 MVP 草案和后续目标，不能逐项视为已交付；具体证据与阶段门槛见 [ROADMAP.md](ROADMAP.md)。

## 目标用户与输入

老人本人或子女可以用自然语言提交起点、终点、出发时间、紧急程度、老人基本情况与行动能力，以及安全、舒适、时间、成本偏好。缺少关键条件时系统应请求补充或说明只能给出有限规划，不得猜测老人能力或实际低空运营状态。

用户故事：作为老人或子女，我希望说明出行条件后看到有依据的安全舒适方案，并能理解其他候选的时间、费用与风险差异。最小状态流为：接收自然语言 → 提取条件与缺项 → 查询来源数据 → 形成候选 → Safety Review → 展示可推荐地面方案、模拟情景或数据不可用说明。输入缺失、数据过期、工具失败、安全审查未通过都属于必须覆盖的边界情形。

## MVP 交付体验

| 能力 | 可观察的验收条件 |
| --- | --- |
| 需求分析 | 结构化显示已知条件、未知条件、行动能力和偏好；不作医疗诊断 |
| 候选方案 | 展示多个可比较选项，并明确推荐、最快、经济标签；没有足够数据时允许少于三个，不虚构候选 |
| 推荐理由 | 说明为何安全与舒适约束优先，列出取舍和未确认信息 |
| 地面—低空—地面路线 | 对低空候选展示接驳、模拟空中段和到达接驳；显示模拟起降点，绝不表示可预订或已获运营许可 |
| 风险提示 | 覆盖天气、行动能力、换乘、运营和数据不确定性；高风险或关键数据缺失时不能给出肯定可行结论 |
| 地图和报告 | CesiumJS 展示 3D 线路，地图与卡片保持来源状态一致；规划报告可导出或生成，保留时间、来源、模拟标记和限制说明 |

## 城市和数据边界

首期只对天津、深圳做代表场景。地面地图、道路、POI、医院、养老机构等只能使用已记录来源且具备使用条件的数据。起降点、低空航线、航班和航空器状态可以模拟，必须标 `SIMULATED_DATA`。查无可靠信息时标 `DATA_UNAVAILABLE`。详细规则见 [DATA_POLICY.md](DATA_POLICY.md)。

## 不在本阶段承诺

真实低空航班预订、实际运营调度、监管许可确认、医疗建议、覆盖全城所有出行情形、复杂分布式部署和 PostGIS 迁移。未来能力需单独决策。

## 关键验收场景

1. 在天津、深圳各至少有一个可追溯地面数据的代表场景，能够生成并解释候选方案。
2. 若候选含模拟低空路段，所有对用户可见的结果均明确标记模拟；若有足够地面数据则提供地面方案比较，缺失真实低空状态时不显示其真实运营可用性。
3. 行动能力、步行容忍度或无障碍条件与候选路线冲突时，推荐必须降级、排除或标出不可确认原因。
4. 关键数据缺失、来源过期或工具失败时，输出 `DATA_UNAVAILABLE` 和可理解原因，不生成伪造的航班、起降点或安全结论。
