## D-001 项目基线

- 状态：已采纳（来自用户项目说明，2026-09-26）
- 决定：产品面向老年人及其子女，提供 AI 驱动的低空综合出行规划。MVP 约 2 个月，首期天津、深圳。取舍顺序为安全 > 舒适 > 可达性 > 时间 > 成本。

## D-006 Sprint 1 技术验收与来源失效处理

- 状态：已采纳（2026-09-27，依据两城 HTTP 演示、27 项测试及 Reviewer 复审）
- 决定：Sprint 1 按验收清单通过技术验收。每城输出有来源的纯地面驾驶估算与显著标记的模拟低空对比，共两类候选；没有独立证据时不制造第三条方案。地面因入口、步行、车辆和天气未知而 `DOWNGRADE`，模拟低空因真实起降/接驳/运营缺失而 `REJECT`，均不标真实可乘坐推荐。
- 数据处理：本地文件读取时按数据集 Schema 校验，状态不一致时关闭受影响候选；低空文件缺失或损坏时保留可独立成立的地面候选并告警。用户“附近”描述保留，OSM 中心点仅作代理；显式但不匹配的坐标不静默替换。
- 影响：Sprint 2 可基于当前接口扩展数据和 MCP 适配；若要升级为真实推荐，须先取得出入口、无障碍、接驳、实时天气及运营证据，并另行评审。Golden 夹具日期来源只在演示与文档中声明，结构化结果独立流转时需后续契约改进。

## D-007 Sprint 1.5 短会话意图与时间范围契约

- 状态：已采纳（2026-09-27，依据产品负责人 Sprint 1.5 指令，要求标准化、会话合并、向后兼容接口）。
- 问题与动机：旧解释器把未标角色的地点猜作起点，行动能力和时间偏好覆盖不足，普通赶时间与医疗急症混同；“明天下午”不能伪造为 15:00。
- 备选 A：保留旧请求结构，只追问精确时刻。代价是指定的三轮场景无法形成完整请求。备选 B（采纳）：保留原有精确时间字段与旧枚举输入，增量加入 `PlanningState`、缺失/不确定项、追问，以及 `departure_time:null + departure_window`；客户端逐轮回传状态。
- 影响：Backend、Needs Interpreter、UserRequest/InterpretationResult Schema、Safety Reviewer 与既有消费者。旧请求继续有效；新枚举由解释器标准输出，旧枚举仅作兼容。`/plan` 对 `MEDICAL_EMERGENCY` 硬阻断。不得把下午窗口视为精确时刻；地点简称无法核实时保留原文且不生成伪路线。无新持久化或外部数据源。
- 迁移/回退：前端尚未接入，可选读取新字段；旧 `text + reference_time` 和旧返回必填字段保留。若回退，应停止发送 `planning_state` 与窗口请求，仍使用旧精确时间请求；不得解除医疗急症阻断。
- 验证：Sprint 1.5 六组人工场景、Schema/合同脚本、解释器与规划安全测试、原 27 项回归；结果以 `docs/PROJECT_STATE.md` 为准。Sprint 2 UI 须等本轮验收结论后启动。
- Sprint 影响：原路线图 Sprint 2 仅列数据/工具边界；按产品负责人本轮“完成验收后再开始 Sprint 2 UI”的指令，将 UI 开发纳入 Sprint 2 阶段草案，具体 UI 范围与验收条件仍待定义，原数据/工具工作保留为并行依赖，不在 Sprint 1.5 实施。

## D-011 Sprint 2 真实线路几何与地点简称的证据边界

- 状态：已采纳（2026-09-27，产品负责人 D-011 补全指令）；下列原提案保留为决策历史，实施以本条新增裁决为准。
- 动机：现有页面能展示基础地图、后端提供的地点和可说明为示意的连接，但指定口语最终演示无法生成路线卡片，也不能绘制真实道路线路。为了达到完整路线地图验收，需决定新增有来源的几何和简称消歧的边界。
- 方案 A（建议）：对现有两城登记 POI 组合取得有来源、带抓取时间与许可的静态地面路线 GeoJSON，提出可选的路段几何字段及兼容规则；前端只绘制有来源的几何并注明非实时、非门到门。地点简称先明确追问校区/出入口或让用户选已登记 POI；有可靠别名证据后再提案受限映射。不得自动把“天津大学”当作卫津路校区入口。
- 方案 B：维持现有 `LocationRef.coordinate` 与示意连接，只提供路线卡片和“位置待确认”；指定简称示例继续返回零候选。无新增数据或接口，但 Sprint 2 的真实线路与最终口语示例路线展示门槛不能标为通过。
- 影响：方案 A 涉及 `data/public/`、数据集 Schema、核心 `Segment`/地图交换契约、Agent 候选、前端地图、来源清单；需先确认数据许可、OSM/OSRM 快照来源和非实时属性。方案 B 维持现有边界。两者均不得改变模拟低空的运营不可用状态、Safety 审查或隐私边界。
- 迁移/回退：若采纳 A，几何字段应可选并版本兼容；缺失或验证失败时回退到本轮的文字说明与示意，不回退到凭空连线。原 HTTP 消费者继续读取既有字段。
- 验证：新增两城几何来源/坐标顺序/时间/数据状态合同测试；路径对照和失败降级测试；浏览器地图切换、无精确入口提示与别名澄清测试；无 P0/P1 安全或可访问性问题后才标路线地图验收通过。
- Sprint 影响与决策人：产品负责人采纳 D-011，授权两城 Golden Scenario 的最小数据补全；Sprint 2 退出门槛仍需产品评审全部通过。
- 裁决：Golden 上下文中允许受控别名映射至唯一 canonical POI 中心点，不等于出入口或接送点；地面 POI 间采用有来源的 OSRM 静态 GeoJSON 快照，模拟起降点采用显式虚构坐标，接驳直线标为 `STRAIGHT_REFERENCE_LINE`，模拟空中直线标为 `SIMULATED_AIR_CORRIDOR`。`Segment` 几何及其证据为可选兼容字段，地图只绘制该字段，几何真实性与路程真实性分别表达。不得改变 Safety 的 `DOWNGRADE`/`REJECT`、制造第三路线或宣称真实低空运营。
- 实施、回退与验证：旧响应仍可缺少几何；无几何时页面显示说明。删除可选几何与别名数据即可回退到旧行为；保留安全和急症阻断。G01–G14、两城 Chrome、合同与无障碍证据见本轮交接和 `PROJECT_STATE.md`。

## D-012 Sprint 3 三维场景与可选外部资源

- 状态：已采纳（2026-09-27，产品负责人 Sprint 3 正式执行指令）。
- 动机：两城演示需要让地面、模拟起降点及未来低空段在空间上可区分，同时维持断网时的完整规划能力。
- 选择：沿用单一 Cesium Viewer 和现有 `Segment.geometry`；地面几何靠近地表，空中二维模拟几何仅在前端派生爬升、巡航、下降的展示高度。展示高度为固定演示参数，不写入规划结果、不交给 Safety、不是批准高度。可选接入 Cesium ion World Terrain 与 OSM Buildings；仅在配置受限只读 token 且网络可用时加载，缺失/失败时回退本地 Cesium 基础地球、同一套路线和文字说明。建筑可关闭。不得新增真实航空服务、第三条路线或外部 LLM。
- 备选：始终只用本地平面底图，稳定但不能展示城市建筑/地形；把外部 3D 作为必需依赖会使无令牌/断网演示失败。均不满足本轮全部体验和降级要求。
- 影响：`frontend/src/components/RouteMap.*`、可选的前端本地配置、数据来源/策略文档与测试。HTTP、Backend、Agent、核心 JSON Schema 不改；模拟路线仍 `REJECT`，地面仍按现有 Safety 结果显示。
- 数据、许可与限制：Cesium ion 资源需有效账户、适用方案、网络与配额；OSM Buildings 署名为 `© OpenStreetMap contributors`，Cesium 自带署名和数据 attribution 必须保持可见。令牌不入库；前端构建变量只能放受限公开读取 token，不能放有私有权限的密钥。官方依据见 [Cesium OSM Buildings](https://cesium.com/platform/cesium-ion/content/cesium-osm-buildings/)、[Cesium World Terrain](https://cesium.com/platform/cesium-ion/content/cesium-world-terrain/)、[Content Usage and Attribution Guide](https://cesium.com/learn/ion/content-usage-and-attribution-guide/) 与 [Token 文档](https://cesium.com/learn/ion/cesium-ion-access-tokens/)。账户许可、现场配额与中国网络可达性尚需在比赛环境实测，不能提前记为通过。
- 迁移/回退：不设 token 或关闭建筑即可退回本地地图；移除可选图层代码不影响原有 API 与数据。验证两城地面/低空高度、Viewer 生命周期、网络/Token 失败、署名、安全文案与浏览器性能；Sprint 3 必须以实测证据决定验收，不能以功能完成代替阶段 PASS。
