## 一、双视角体验记录

### Persona A（老人本人：大字体需求、不熟悉科技产品）

1. 首屏（01）：大标题"今天想去哪里？"+ 欢迎语"告诉我您想几点从哪里去哪里，以及老人的行动情况"。输入框在首屏内可见，有示例占位文字。能知道"在左下方的框里打字"。
2. 150% 缩放（14/15）：布局不溢出，文字明显变大可读，方案卡、按钮均可用。
3. 打字输入是唯一交互方式；追问只能靠继续打字回答，无快捷按钮。对老人有负担。
4. 结果页术语理解困难："存在限制，已降低推荐优先级""公开 POI 中心点""OSRM 模型快照"（后者出现在"为什么这样规划"正文中）。老人很难据此判断"到底能不能按这个走"。
5. 结果出现后对话被折叠为"查看对话记录"，想补充信息要滚动到底部输入框，路径不直观。
6. 积极面：模拟方案有紫色横幅"未来场景演示，当前不可据此购票或乘坐"，大字体下同样醒目。

### Persona B（成年子女：帮父母规划）

1. 流程顺畅：一句话输入 → 需求卡 → 2 个方案，三轮短句追问也自然（02/03）。
2. 证据透明度极高：每个方案有"安全审查 + 数据来源 + 逐条原因 + 数据说明 + 为什么这样规划"，能清楚分辨"公开数据/模拟数据"。
3. 主要摩擦：结果返回瞬间地图停留在全国视图或上一个城市数秒（详见 P0-1/P1-1），"路线在哪"这一最核心问题不能立刻回答；地图面板里"福建省边界查询成功（421 段边界）"与行程无关，引起"为什么提到福建"的困惑。
4. "查看完整路线/查看起点街区"按钮实用；但按钮在地图浮层里，首次出现时机晚于结果。

## 三、P0–P3 问题清单

### P0

- **P0-1 重新规划后，地图残留上一个城市 4–10 秒，期间顶部状态条已显示新方案。**
  序列：深圳规划完成（地图正确定到深圳，21）→ 点"重新规划"→ 输入天津 Golden → 结果返回：左侧已显示天津需求与方案，右侧地图仍显示深圳街区（22=t0、23=t4s 完全相同），约 10 秒后才切到天津（24）。反向同样复现（17：天津之后规划深圳，地图停留天津街区）。
  影响：错误城市地图与新规划结果同屏，无任何"地图正在切换"提示，属现实正确性误导；老人/子女都可能把旧城市地图当成"这次的路线"。

### P1

- **P1-1 首次规划结果返回后，地图数秒内无有效信息或路线不可见。**
  结果出现 t0：地图近空白（灰底仅见福建省紫边界，19；天津首轮为全国视图，04）；t4s：华南/华北超大视野，起终点 marker 重叠成一个点，路线形状不可见（20/05）；约 t10s 才到街区级（21）。用户在最想确认"路线在哪"的时刻看不到路线，只能依赖左侧文字。
- **P1-2 系统接受"过去的出发时间"且无任何提示。**
  审查日 2026-09-29，输入 2026-09-28 15:00 直接出方案，需求卡仅显示"9/28 15:00"（09），无"该时间已过去/是否指明年"的确认。现实正确性问题：为已过去的时刻生成"出行方案"。

### P2

- **P2-1 安全结论措辞对目标用户偏术语，且缺少"两方案谁更接近现实"的直白对比。**
  卡片小字"存在限制，已降低推荐优先级"（DOWNGRADE 译文）老人难以理解；没有任何一处直说"地面方案比模拟低空更接近现实可参考，但出发前仍需人工核实"。信息都在，结论要用户自己拼。
- **P2-2 地图面板向用户暴露内部能力核验，且与行程无关。**
  "地图能力核验：福建省边界查询成功（421 段边界）"（17 地图面板文本），且紫色福建省高亮常驻首屏与结果地图（01/02/05/20）。与天津/深圳行程无关，干扰注意力，可能引发"我的路线怎么在福建"的误解。
- **P2-3 "为什么这样规划"正文存在机器拼接语。**
  例："真实天气、可飞条件、运营状态和费用均为 暂无可靠数据。""步行：暂无可靠数据，未知。"（pass1 抓取的 ROUTE A/B DETAIL TEXT）。枚举值翻译后内联进句子，读感生硬，老人/子女均减分。

### P3

- **P3-1** 追问仅纯文本，无快捷回复/选项按钮，老人打字负担重。
- **P3-2** 3D 立体视图中深圳"出发地"与"模拟起降点 A"标签重叠（18）。
- **P3-3** 浏览器控制台 1 条 404 资源错误 + 1 条 Canvas2D willReadFrequently 警告（pass4 采集）；404 资源未定位，疑似 favicon。
- **P3-4** 结果页对话被折叠进"查看对话记录"，继续补充/修改需求的入口只剩底部输入框，无引导；"01/03→03/03"步骤语义未解释。

## 四、3D 误导风险清单（只记录，不改代码）

| # | 风险点 | 具体 UI 元素/文案 | 现有缓解 | 残留风险 |
|---|--------|------------------|----------|----------|
| R1 | 模拟低空航迹被误认为真实可飞航线 | 立体视图紫色虚线拱形航迹（视觉高度 800m），图例"模拟低空"，面板标题"地面 + 未来低空场景"（07/10/18） | 四重缓解：顶部状态条"当前不建议采用"；面板"仅供情景演示，不代表真实航线或可乘坐服务"；数据说明"高度只用于模拟展示，不代表获批航线或可飞条件"；卡片紫 banner"不可据此购票或乘坐" | **低**：截图分享时免责声明可能不在画面内；航迹形态（爬升-巡航-下降剖面）本身像真实飞行 |
| R2 | 模拟起降点被误认为真实设施 | 紫色圆点标记"模拟起降点 A/B"（07/10） | 点击/按钮详情写"仅用于 SilverSky 场景演示，非真实运营设施；位置为模拟坐标"（13） | **低**：标记本身名称含"模拟"，缓解充分 |
| R3 | 高德"城市 3D"楼块视图被误读为"低空可用视角" | 地图浮层标题"高德地图 · 城市 3D（设备支持时）"（01/04） | 折叠的"数据说明"内写"楼块……不证明地点可达或航线可飞"（17 地图面板） | **低-中**：主视图常驻文案只强调"3D"，否定性说明藏在折叠详情里 |
| R4 | Cesium 底图真实性 | 绿色无纹理地球 + "CESIUM ion"角标（07/18） | 不像真实城市，反而降低误信 | **低** |
| R5 | 视角切换按钮语义 | "真实城市地图 / 立体旅程示意"（01） | "示意"二字明确 | **低**：命名合格 |

3D 总体结论：模拟低空在立体视图中的**视觉真实感**（拱形航迹、3D 空间）与**文案否定**之间存在天然张力，但当前文案缓解密度高、位置醒目（顶条+面板+banner+详情四层），误导风险整体为低；最大残留是 R1 的截图外传播场景与 R3 的主视图"城市 3D"表述。
