# 真实用户测试协议（User Test Protocol）

日期：2026-09-29
状态：**资料准备完成，未执行任何真实用户测试**（不得声称已测试）
执行角色：WorkBuddy Reality Research Agent（只准备，不实施）

## 0. 通用说明

- 对象：Persona A = 60 岁以上老人本人；Persona B = 成年子女（为父母规划）。
- 环境：本地 Demo（2D 主决策视图），测试前主持人不讲解用法。
- 记录方式：主持人观察 + 屏幕录制；**Think-aloud**（鼓励说出想法，老人组不强制）。
- 每个任务结束主持人记录指标，中途不可提示（Task 内 help_requested 记录的是用户主动求助）。
- 终止条件：用户明确表示无法继续，或单任务超过 5 分钟。

## 记录指标（每个任务）

| 字段 | 含义 |
|---|---|
| completion_time | 秒 |
| completed | 独立完成 / 提示后完成 / 未完成 |
| help_requested | 用户主动求助次数 |
| wrong_clicks | 与任务无关的点击次数 |
| route_misunderstanding | 是否错误理解路线含义（Y/N + 描述） |
| simulation_misunderstanding | 是否把模拟低空当成现可乘坐（Y/N + 描述） |
| entrance_confusion | 是否把 POI 点当作入口/上下车点（Y/N + 描述） |
| next_step_confusion | 是否不知道下一步做什么（Y/N + 描述） |
| ease_score | 任务后自评 1–5（1=很难，5=很容易） |

## A. Elderly Test Script（老人测试脚本）

主持人口吻：慢速、一次只说一句；任务卡用不小于 18pt 字体打印。

### Task 1 找到输入位置
- 任务卡：「这个页面是帮您规划出门看病的。请您告诉我，您会点哪里、或者在哪里打字，告诉它您想去哪？」
- 通过标准：60 秒内指向或点击对话输入区。
- 观察：是否犹豫、是否先点地图、是否误点 3D 视图。

### Task 2 输入真实出行任务
- 任务卡（口述 + 文字）：「请您告诉它：明天下午 3 点，我要从天津大学卫津路校区去天津医科大学总医院看病。」（深圳参与者用深圳市养老护理院 → 北京大学深圳医院）
- 通过标准：以任意自然语言形式发出起终点与时间。
- 观察：打字困难程度、是否倾向语音（当前是否支持需记录）、措辞是否被系统正确理解。

### Task 3 完成系统追问
- 任务：若系统追问（如出行方式、陪同、时间窗），回答追问直至出现方案。
- 通过标准：无主持人帮助下完成全部追问。
- 观察：追问文案是否被听懂；是否重复回答；是否出现"它为什么又问我"。

### Task 4 解释系统给出的路线
- 任务卡：「请您用自己的话说说，屏幕上这条路是什么意思？从哪到哪？怎么去？」
- 通过标准：能说出起终点、地面路线为参考、并能指出这是"道路模型估算"而非导航。
- 观察：是否注意「OSM 中心点不是入口」类声明；entrance_confusion。

### Task 5 指出哪个方案现在可以参考
- 任务卡：「这些方案里，您觉得哪个是您现在真的能用的？指给我看。」
- 通过标准：选中地面方案，并说出模拟低空不可用（或被拒）。
- 观察：route_misunderstanding。

### Task 6 指出哪个方案只是未来模拟
- 任务卡：「这里面有没有一个方案是现在坐不了、只是演示的？」
- 通过标准：指出模拟低空方案，并复述"现在不能坐"。
- 观察：simulation_misunderstanding（核心安全指标）。

### Task 7 说明下一步会做什么
- 任务卡：「看完这些，您接下来想做什么？在这个页面上您会点哪里？」
- 通过标准：说出一个明确动作（修改地点/重新规划/让子女看/退出）。
- 观察：next_step_confusion。

### 结束访谈（3 分钟）
1. 整个过程哪里最难？
2. 哪句话您没看懂？
3. 您敢不敢照着这个页面自己出门？为什么？

## B. Adult Child Test Script（成年子女测试脚本）

任务结构与老人版相同，措辞调整为「帮父母规划」视角：

### Task 1 找到输入位置
- 同 A。预期更快，但仍记录 completion_time 与 wrong_clicks。

### Task 2 输入真实出行任务
- 任务卡：「请帮您的母亲规划：明天下午 3 点从天津大学卫津路校区到天津医科大学总医院复诊，她 78 岁、行动不方便、需要您陪同。」
- 观察：是否主动补充无障碍/陪同信息；系统是否承接。

### Task 3 完成系统追问
- 同 A。观察：追问是否对「陪同/行动能力」有效利用。

### Task 4 解释系统给出的路线
- 追加问题：「这条路线的距离和时间，您会多大程度相信？为什么？」（测试对数据声明的信任校准）

### Task 5 指出哪个方案现在可以参考
- 同 A。追加：「您会把哪个方案直接发给司机/约车平台？」

### Task 6 指出哪个方案只是未来模拟
- 同 A。追加：「如果只给您母亲看这个页面，您担心她误会哪一点？」

### Task 7 说明下一步会做什么
- 同 A。追加：「要让您放心用它，还缺什么信息？」（预期答案：入口、上下车点、无障碍——用于验证需求排序）

### 结束访谈（3 分钟）
1. 您会放心让老人单独使用吗？
2. 哪些声明/标注您注意到了？哪些没注意？
3. 和直接用高德/打车软件比，它的增量价值是什么？
