状态：2026-09-27 已由产品负责人启动，实施与验收分开记录。范围依据本轮 Sprint 2 总指令，项目状态以 [PROJECT_STATE.md](PROJECT_STATE.md) 为准。

## 用户任务与边界

老年用户或子女在桌面浏览器输入自然语言，按系统追问补全本次出行信息，阅读需求摘要、候选路线、安全审查和来源状态，并在地图中查看有证据的位置与可绘制线段。刷新或“重新规划”可清除当前会话。前端不展示 JSON、Schema 或内部 Agent 推理。

输入为自然语言、后端解释结果及本次 `planning_state`；状态包括首次、解释中、待补充、冲突待澄清、医疗急症、规划中、有结果、零候选及服务错误。输出只采用后端返回的需求、问题、路线、安全和数据状态；缺字段、位置或线路几何时明确说明未知。当前不含登录、长期记忆、购票、真实低空运营、移动 App、高精度数字孪生或新 LLM 服务。

## 安全和数据验收口径

- 只有 `planning_allowed:true` 且 `user_request` 非空、非医疗急症才能进入 `/plan`。前端不重复实现槽位追问逻辑；冲突时显示后端问题。
- `MEDICAL_EMERGENCY` 停止普通规划并提示联系 120/当地紧急医疗服务；后端 422 保持第二道阻断。
- 模拟低空显著标为未来场景演示，不提供购票或真实可乘坐暗示。`PASS`、`DOWNGRADE`、`REJECT`、`UNKNOWN` 与四种 `DataStatus` 均有文字表达。
- 只有真实地面、Safety `PASS` 且后端标记 `RECOMMENDED` 的候选可显示“推荐”；无此候选时显示暂无满足条件的真实方案。
- 当前地面快照无 GeoJSON 几何，模拟起降点无坐标，POI 中心点并非入口。地图只能绘制已返回坐标和明确标注的示意连接；无坐标时显示“位置待确认”，不得补造路线。

## 验收记录规则

F01–F20 与总指令二十项验收条件均需记录“通过 / 未通过 / 未验证”和证据。自动化测试、浏览器检查、人工无障碍与产品评审分别记载；技术通过不自动等于产品验收。零候选允许是正确安全输出，不能为演示制造第三条路线。
