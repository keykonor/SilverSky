# Code Change Verification

## 工作方式

1. 确认变更目标及文件范围，对照 `docs/PROJECT_STATE.md`、`docs/DECISIONS.md`、`docs/INTERFACES.md` 检查 MVP 范围和架构一致性。
2. 查看差异与依赖方，核对接口是否按已确认契约修改；未批准的破坏性接口或重大架构变化不能作为已验收变更。
3. 按风险选择必要验证：有针对性的测试、类型/静态检查、契约样例、手工路径或运行结果。测试应覆盖可观察行为，尤其是错误、缺失数据、真实/模拟标记及安全降级；不为低影响可逆变更机械添加测试。
4. 记录实际执行的命令、结果及未执行项的原因。区分“已提交”“验证通过”“已集成”“阶段验收”。
5. 有失败或证据不足时列出具体待修项，交回负责方；通过后才更新 `docs/PROJECT_STATE.md` 的完成状态。

## 不负责

不定义新需求、不批准重大架构决策，也不把没有运行过的测试写成通过。
