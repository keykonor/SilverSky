# API Contract

## 契约原则

以 `docs/INTERFACES.md` 为项目级接口索引。接口可以是 HTTP、MCP 工具或 JSON / GeoJSON 文件；契约必须区分“提案”“已确认”“已实现”“已验证”。目前未定义的端点、字段和工具名称不得臆造为既成事实。

## 工作方式

1. 标明提供方、消费方、用途、契约负责人和状态。
2. 对具体契约说明输入/输出结构、类型与单位、坐标系与时区、必填/可选、错误与不可用响应、版本/兼容策略，并给出最小有效样例。只写当前边界需要的字段。
3. 涉及城市、交通或低空数据时明确来源、更新时间、真实/模拟属性、适用范围及用户可见标记；与 `safety-data-integrity` 对齐。
4. 变更前列出消费者和迁移影响。破坏性变化先进入 `docs/DECISIONS.md` 待决，明确批准后再更新契约和实现。
5. 契约确认后，把对应验证责任交给 `code-change-verification`，并在 `docs/INTERFACES.md` 留下证据位置。

## 不负责

不决定产品优先级，不代替具体模块的内部类型设计，也不把示例数据视为真实交通运营数据。
